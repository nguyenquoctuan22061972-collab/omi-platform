# PRD-004: Frontend Dashboard

> Phái sinh từ PRD-001 §8 (5 màn hình) + capability KPI (CR-001). Không phá PRD-001..003.

## 1. Tên Module
Frontend Dashboard

## 2. Mục tiêu
Hoàn thiện Dashboard quản trị OMI Platform: hiển thị KPI realtime từ CRM Core, điều
hướng tới các màn hình quản trị, responsive desktop/mobile.

## 3. Người dùng
CEO (xem KPI), Manager/Sales/CSKH (điều hướng nghiệp vụ), Admin.

## 4. Đầu vào
`GET {CRM_BASE}/dashboard/kpi` (CR-001). Fallback mock data khi chưa cấu hình.

## 5. Đầu ra
- Màn Dashboard: KPI cards (contacts, messages, win rate) + biểu đồ pipeline theo stage.
- Điều hướng tới Contacts / Inbox / Pipeline (route skeleton theo wireframe §8).

## 6. UI/UX
- Responsive: desktop (grid nhiều cột) + mobile (1 cột, nav thu gọn).
- Xem `docs/Product/Frontend-Dashboard-uiux.md`.

## 7. Kiến trúc FE
Vanilla JS (không build/không phụ thuộc mạng): component map + hash router + store.
Integration layer gọi CR-001, có mock fallback. Xem TechSpec.

## 8. Database
Không sở hữu DB. Chỉ đọc KPI qua API.

## 9. Workflow
1. App load → đọc config `CRM_BASE`.
2. Store fetch KPI (api layer) → mock nếu lỗi/chưa cấu hình.
3. Render KPI cards + pipeline chart.
4. Router chuyển màn theo hash.
5. Refresh định kỳ (poll) → cập nhật store → re-render.

## 10. Test Case (TC1-TC10 — acceptance)
TC1 index.html + viewport responsive · TC2 root mount · TC3 api gọi `/dashboard/kpi` ·
TC4 dùng config `CRM_BASE` (không hardcode host) · TC5 mock/kpi.json hợp lệ đủ trường ·
TC6 store có subscribe/set · TC7 router có bảng route · TC8 đủ component (nav/kpiCards/
pipelineChart/overview) · TC9 không secret/host hardcode · TC10 config.example.js +
CSS có media query.

## 11. Risk
- API lỗi/timeout → mock fallback + trạng thái lỗi trên UI (không trắng màn).
- CORS khi gọi CRM khác origin → cấu hình CORS ở Deployment (ngoài scope).
- Sai số liệu → chỉ hiển thị, nguồn sự thật ở CRM Core.

## 12. Ưu tiên
Hỗ trợ go-live WF050 (cùng dùng CR-001). Không đổi PRD-001..003.
